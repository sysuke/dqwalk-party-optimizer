# ダメージと結果画面の再点検（2026-11-13）

目的は、所持品から新コンテンツに持ち込める装備・手順を出し、結果から調整できること。弱い通常下限の小幅改善やテスト数の増加を、実戦の参考品質の代わりにしない。

## 点検結果

1. **計算精度と探索品質は別の問題。** 物理は公開検証式、呪文はスキル別の基礎威力・代表暴走倍率を使用。通常の確率不発とゾーン・暴走・指定AI成立時を混ぜて比較できない。呪文の大火力は準備・継承・役割・実現条件を一組として探索する必要がある。現行の強い参考手順比較を維持する。
2. **残HPと火力の意味が一致していない箇所。** 単体・非シールドの実適用ダメージへ、敵の残HPを超える余剰まで加算していた。火力は元値を残し、実適用だけ残HPで制限する。複数敵・シールドには既存の残HP制限がある。
3. **大きい数字だけでは手順の実現性を判断できない。** 表示順の火力が、速度モデルの可能な全順序の上限より高いことがある。数字の近くに順序別範囲と注意を出す。味方順成立・敵への先制・生存・確率条件を同じ成功判定にはまとめない。
4. **ダメージが低い原因を調べる入口が深い。** 誰が何回攻撃したか、最大攻撃に適用した種別・属性耐性とSHTガードを、実行ログから要約する。倍率を外した推定値や「何倍出るはず」という逆算は作らない。
5. **9ターンの手順を全部並べると結果調整が遠い。** ターンごとの合計は一覧で残し、操作詳細だけ開く。第1ターンを初期展開し、そのほかは折り畳む。アンコール・自動攻撃・各行動詳細は維持する。

## 今回の変更

各候補に「表示手順の火力／実際に減らすHP／味方順」をまとめた結果概要を導入。成立に必要な状態を数字の直下へ配置。内訳は一つの折り畳みへまとめ、攻撃回数と寄与、最大攻撃に適用された軽減倍率を表示する。超暴走・マナを含む幅は代表倍率での計算と明記する。候補選択・既存の編集・保存形式を維持する。

集計は実行ログのみを使う。詠唱を攻撃合計へ再加算せず、敵攻撃も除外。攻撃のない補助役は攻撃0回と表示し、担当価値の低さという判定には使わない。主力以外にかかった耐性まで最大攻撃の軽減として表示しない。

式や耐性を目標ダメージへ合わせる変更、探索予算拡張はしていない。単体実適用の修正は、HPを削った量を参照する比較へ影響し得るため全体回帰を実施する。

## 次の優先順位

1. 計算の信頼性：実測可能な1攻撃の条件を固定して、基礎値→加算群→乗算群→各詠唱→丸め→シールドまで照合する。未対応効果は個別に追加し、確率不明を確定扱いしない。
2. 推薦品質：実戦に近い強い固定手順を基準に、通常・条件成立時・順序別最低値を別々に比較する。弱いケースの相対改善を主指標にしない。
3. 操作：候補の装備代替と、保存しない敵・状態の試算変更を同じ結果画面で完結させる。現状の所持数・レベル編集は保存を伴うことを維持表示。
4. 保守：肥大化したparty.jsの結果概要・詳細描画を順次分離し、動作を確認してから旧重複表示を整理する。計算全置換・保存ID削除を先に行わない。

全面書き換えを先に行うより、計算と表示の境界・実測の照合単位を整え、再計算できる状態で画面を置き換える方針とする。
