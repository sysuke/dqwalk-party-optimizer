# 役割を組み合わせた攻略案の候補生成

## 変更

既存の単独火力による編成順位とは別に、主力＋領域＋ロンド＋強化、主力＋ロンド＋強化＋アンコール等の役割を満たす編成を最大8件組む。耐久目標では回復役を含む型も候補にする。役割は習得済みスキルの種類から選び、特定の武器名だけで完成編成を決めない。

主力候補は攻撃スキルの種類と育成済みの担当者を分けて保持する。同じ担当者・スキルの装備違いだけで枠を使い切らない。各主力16件、全体128件まで所持数と能力を検査する。

装備の競合では主力・一般補助の装備から解放し、必要な強化と領域担当を後に残す。解放後に全員の能力・主力スキル・必要な補助スキル・指定領域色を再確認し、役割を失った候補は棄却する。装備を増やさず、プロフィールも変更しない。

生成した編成について、既存の攻撃・補助手順生成と通常の戦闘計算を使ってMP・バフ持続・補助対象・シールド等を再評価する。倍率や発動率を新たに付与しない。

## 統合方法の判断

初期実験で新編成を従来の先頭へ挿入すると、限られた探索枠から既存の有望案が押し出され、白領域の構造ケースが300,496から266,773へ低下した。この統合方法は採用しない。

現在は既存の探索を先に行い、その結果を保持して、残り件数と残り時間がある場合だけ新しい攻略案を追加比較する。総件数・締切は増やさない。余りがなければ未実行になる。`strategyTeams` に候補数・在庫確認件数・手順比較件数・主力スキルを返す。これは探索全体の置換完了ではない。

## 初期品質ケース

`tests/fixtures/search-quality.cjs` に `spell-roles-2t` を追加。参考記事の白領域・ロンド・真魔解放・祈り・おうえん・アンコールの構造を使い、装備の所持数を参考手順で使用する個数だけに絞る。ユーザーの実所持品や記事ダメージの再現ではない。

比較方法：

```
node scripts/benchmark-search.cjs --spell-only --without-strategy-teams
node scripts/benchmark-search.cjs --spell-only
```

同じ1,000手順上限で、追加比較なしは880件・300,496、追加比較ありは935件・300,496。追加で8編成から55件の手順を比較し、既存の最良値を保持した。このケースで火力が向上したとは扱わない。参考固定手順は265,328。両者とも行動順未達であり、実行可能な攻略品質の合格ではない。

`tests/strategy-teams.cjs` では低火力補助の保持、役割を失う装備解放の棄却、色・締切の条件、1個だけの領域用こころの予約、生成編成の全手順での火力改善とMP・再計算一致を検証する。最後の改善は構造ケースであり実機火力ではない。
