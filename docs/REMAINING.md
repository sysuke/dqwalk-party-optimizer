## 最優先：実測から計算の差を切り分ける

0.51で物理1発の計算過程・装備スナップショットを照合記録へ追加。会心ガード適用前と最終値を区別する。

0.50で会心ガード不明・代表倍率・未完のモデルは照合保留と表示。実測にあるアクセ3件を追加し、未接続効果は明示した。

実測は提供済み。黒き偽竜グレイナルの551・6,055、古代の遺跡キラーマシン2の43,197・67,674を扱う。最後の例は領域が「おそらく超越領域」であり、ゾーンだけの厳密な比較実験ではない。従来文書の「実測値未提供」は誤り。

- [グレイナル照合](GREYNARL-MEASUREMENT.md)、[キラーマシン2照合](KILLER-MACHINE2-MEASUREMENT.md)、[追加測定計画](MEASUREMENT-TEST-PLAN.md)を基準に、敵強化・会心ガード・通常/超越領域・テンションを固定する。
- 次の実機測定は、同じ装備・攻撃力・敵強化で、通常/超越領域を画面で確認し、ゾーン有無だけを変えた各数回。1発/全ヒット合計、攻撃直前の状態、ターンを保存する。
- 現在の回帰テスト合格は実装の一貫性。全条件で実機に一致したことを意味しない。100万という期待値へ合わせる倍率修正は行わない。

## 次：探索結果を実行可能な装備・順番へ近づける

- 0.44〜0.48で、火力目標からの逆算、こころ・職業・補助手順の同時修正、4枚同時ブレイク、待機/小火力の補助置換を実装した。全組合せの最適解ではなく予算内の近似探索。
- 速度未達でも火力比較を許す設定がある。祈り→特盛→ロンド→主力という並びが見つかっても、その速度を所持装備で実現できる保証はない。火力を維持した速度装備の再探索が必要。
- 弱い攻撃を補助へ替える15%の基準は候補抽出用。候補の取りこぼしを小規模全列挙と比較し、複数の補助を同時に替える探索を増やす。
- 4枚破壊はHP消滅と別。シールド破壊前のHP制限、次ターンの解除・敵バフ・敵行動を含めた実戦検証が必要。
- 共有時間・件数上限、キャッシュは実装済み。低性能PCの処理時間・メモリ上限、内部ループの終了応答を計測する。

## データと状態管理

- 全11職の基礎能力は仮値を含む。実測表示能力、こころ道、永続・熟練度を分離して収録する。レベルだけで正確な能力になる状態ではない。
- 18章の代表敵、鉱脈の深度未指定データ、敵守備力・速度・被ダメージ上限の仮値を優先して埋める。敵のテンション・会心ガード・解除等の遷移を実装する。
- ゾーン/テンション成立時と非成立時の比較は実装済み。発動率・相関・AI選択率が不明なケースの実現率は未算定とする。50%以上かどうかは未入力率から推定しない。
- 超暴走・マナの代表倍率、丸め、詠唱ごとの更新、暴走魔法陣、こころ道の全パッシブ、祈りの他職対応は未完了。
- プチおうえんは今回常時補正と区別して未接続。通常のおうえんで代用しない。
- 付与・延長・失効・追加行動の持続を個別に実機確認する。防御の被ダメージ軽減、装備耐性からの被ダメージ計算は未対応。
- 旧IDと新IDの同名在庫が残るものがある。保存データ互換の移行が必要で、IDを単純削除しない。

## 保守・公開

- 未使用の旧配信コード4本を削除。旧v8計算は回帰テスト専用のfixtureへ移動。現行のsolverとauto-optimizerは画面から使用中なので保持。
- 最終読み込み後のデータ監査を `npm run audit:data` で再実行できる。古い仮値が後から上書きされる構造に注意。カタログの単一管理元への段階的統合が残る。
- GitHub Pagesの設定は別課題。ワークフロー設置だけでは公開成功を意味しない。所有者限定Sitesの公開範囲は維持する。
