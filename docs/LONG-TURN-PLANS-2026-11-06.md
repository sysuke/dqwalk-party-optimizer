# 長期戦の補助対象・行動順を最後に見直す

## 見つかった取りこぼし

零式5ターンの標準プロフィールでは、前回の最良値は202,880だった。装備と敵条件を変えず、各ターンの行動と同じターン内の順序を別の比較処理で調べると、267,253のMPを満たす手順が見つかった。「特盛一丁！」を銃剣へ渡す、ロンドの次に動く相手を変える、補助が不要なターンに攻撃へ戻す、といった差がある。

長期戦では役割装備の追加や一まとまりの準備手順を比較しても、最後に残った手順の全ターンを細かく直す工程がなかった。既存の2ターン用の `PlanSearch19.refine` はそのまま長期戦へ使える実装ではないため、長期戦専用の限定修正を追加した。

## 変更

- 3〜9ターンの最良候補について、装備・職業・配置・敵条件を保ち、単独行動を習得済みの攻撃・補助・準備・回復へ置き換える。
- 味方への補助対象も比較する。ダーマの祈りは対応する大魔道士だけを対象にする。
- 同じターンの行動順を交換する。アンコール等の追加行動は既存の組を保って移す。新しいアンコールやAI準備の組はこの工程で追加しない。
- 変更案は毎回、戦闘全体でMP・バフ持続・シールド・生存等を再計算する。資源不成立を採用せず、行動順必須なら順序・先制も満たす案だけを採用する。
- 総戦闘評価枠から15%、最大192件を予約し、既存工程もその枠を使い切れないようにする。前工程の評価期限から最大2秒・残時間の10%を予約する。全体の件数上限と締切は増やさない。
- 低火力の人物から、補助対象と行動を優先して最大2巡する。単独行動の比較と同ターン順序の比較に分けて枠を使う。
- `longPlanRefinement:false` で比較用に無効化できる。返却する `longPlanRefinement` には評価・成立・改善・順序交換の件数、前後の火力を記録する。

## 同じ上限での比較

```
npm run benchmark:roles -- --bahamut-turns
node tests/long-turn-plans.cjs
```

零式・通常条件・標準のお試しプロフィール・5ターン・全戦闘評価上限1,000件・装備候補4,000件指定・30秒上限で比較した。無効時202,880に対し、有効時261,676。修正工程は125件、うち順序交換60件を評価し、全体は975件だった。固定参考手順267,253の約97.9%。参考手順と旧手順を固定ファイルに保存し、毎回同じ計算器で再生する。

装備・職業・入力プロフィールは不変で、敵耐性や計算式も変更していない。未知の確率効果を付与していない。ただし、装備由来の開幕効果や「極限集中」のように実行した確定ゾーンは従来どおり適用する。

今回のケースの行動順・先制は依然未達で、敵の領域遷移やガード解除等も未対応。利用者の保存プロフィールのJSONは未取得であり、報告画像そのものや実測ダメージの再現ではない。火力は約29%改善したが、数百万単位の実機火力を再現したとも、低火力問題全体を解決したとも扱わない。

## 残る制限

全行動列を列挙する最適化ではない。枠内で主力へ装備を集め直す工程、新しい再行動の生成、ターンをまたぐ行動移動、複数行動を同時に変えないと改善しない手順は取りこぼしうる。固定参考手順との差5,577も残る。次は通常条件のさらに強い固定編成と、共有装備・複数補助の同時成立を照合する。

既存の物理MP制約の構造ケースも比較し、5ターン488,336・9ターン558,348を有効/無効の両方で維持した。この2件では最良火力の改善はなく、探索品質全般の改善を示す結果ではない。`scripts/benchmark-search.cjs --without-long-plan-refinement` で既存ケース側も無効比較できる。

## 残り枠を使った3巡目（同日）

2巡で打ち切ると、改善後に新たに有効になる行動を見直せず、評価枠が余っていても止まっていた。改善が続き、時間と評価枠が残っている場合は最大3巡まで比較する。予約枠15%・最大192件、全体の上限と締切は変更しない。`longPlanThirdPass:false` で従来の2巡と比較できる。

```
npm run benchmark:roles -- --bahamut-third-pass
```

同じ零式5ターン・1,000件上限では、2巡の261,676（全体975件）に対し、3巡は267,253（全体1,000件）。修正工程150件を使い、固定参考手順に一致した。装備、敵条件、計算式は同じ。返却する `rounds` と `stopReason` で、巡回数と停止理由（期限・評価枠・巡回内で改善なし・巡回上限）を区別する。

固定参考手順との差は解消したが、その手順は最適解や実機再現ではなく、行動順・先制は未達のまま。低火力問題全体の解決ではない。追加の25評価で約2.1%改善した結果であり、速度向上や全条件での改善を示すものではない。

同日に[敵の掲載資料](https://9db.jp/dqwalk/data/20605)も再確認した。SHTガードの99%軽減とゾーン併用時も軽減される記載を確認し、この倍率は変更していない。ガード解除や敵領域等の未対応条件を補うには、引き続き別の状態遷移モデルが必要。
