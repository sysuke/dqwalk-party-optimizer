# 下限の小差ではなく、条件と準備を含む大火力案を残す

## 方針の修正

利用者の目的は、新コンテンツで所持品から試す価値のある構成と手順を得ること。零式5ターンの26万前後の下限手順を細かく改善しても、その目的を十分に満たしていなかった。下限側の回帰ケースは残すが、推薦品質の主な到達点とは扱わない。

まず独立に、主力の装備、領域、補助対象、真魔解放のAI攻撃、消費MPを揃えた呪文手順を作成した。標準のお試しプロフィールと零式の初期耐性を使い、主力ゾーン・呪文暴走・AIが指定呪文を選ぶ場合に2,260,628の参考火力を計算できた。この条件の発動率と維持率は不明で、通常条件の保証値でも実測再現でもない。

## 見つかった取りこぼしと修正

- 所持品が競合すると、主力の装備を最初に外していた。領域の色や補助技に必須のこころ・防具だけを保護し、それ以外は補助役から外す。主力の火力装備を優先し、最後に全員の所持数・能力・必要技能を再検査する。
- 同じ攻撃名の候補をまとめた結果、継承呪文を持つパラドクス構成が、準備前の火力だけで他の杖へ置き換わっていた。AI比較を許可した場合は、実在する継承＋自動呪文の役割を1枠確保し、その構成が後段の編成数制限でも落ちないようにする。
- 主力・おうえん・祈り・ロンドを揃えても、各スキルを個別に変える探索では成立する準備順を見つけにくかった。全員が必要技能を持つ場合だけ、真魔解放の自動攻撃と通常の呪文、前ターンの攻魔補助、おうえん、祈り、ロンドを含む完全な行動列を生成する。初期発動と終盤発動を比較する。
- この準備案は、他の手順探索で枠や時間を使い切る前に最大24件を検査する。既存の全体評価枠に含め、上限は増やさない。未知の発動効果をこの工程で新たに付与しない。
- 返却値 `burstSeedCalls` で先に検査した準備案の件数を数える。`lateSpellBursts:false` で完全な呪文準備案の生成だけを無効化し、同じ条件で比較できる。

## 画面

比較する戦闘状態に「主力ゾーン・暴走成立時（テンション100を仮定しない）」を追加した。詳細設定を開かずに、紫領域・主力ゾーン・暴走・指定AI呪文を含む火力案を比較できる。

連続呪文は確率成功を仮定せず、祈り等の実際の手順で付与する。やまびこもこのプリセットでは独立した確率成功として追加せず、主力のゾーン状態による既存モデルの効果を使う。テンション100は指定しない。SHTガード99%や敵耐性を緩和して数字を増やさない。

結果の見出しを「条件付きの火力案と手順」とし、発動率・維持・討伐成功率が未算定と明記する。通常条件の既定値は変更しない。比較欄の「ゾーンなし」は、暴走等の他条件を維持した比較であり、無条件の火力とは説明しない。

領域を出すために得意でない武器を持つ補助役もあるため、結果カードへ「開幕の領域」を追加した。今回の武器が攻撃用か領域・補助用かを実際の行動と一緒に確認できる。

## 検証

```
npm run benchmark:roles -- --bahamut-conditional
node tests/conditional-burst.cjs
```

標準プロフィール・零式・5ターン・同じ新プリセット・全戦闘評価上限1,000件・装備候補4,000件指定で比較する。完全な呪文準備案の生成無効時309,842、有効時3,556,623。これは同じ新プリセット内で生成工程だけを切り替えた比較で、通常条件26万から355万へ改善したという意味ではない。

有効時は全体999件、先行準備案8件。独立に固定した参考2,260,628を超える結果が残り、最良案は大魔道士のパラドクス＋継承ラブ・ストリーム、紫領域、祈り、ロンド、おうえん等を含む。全手順を再生し、MP・所持数・ダメージの一致を確認する。プロフィールは変更しない。成功率は `null`、`conditionsMet` は `false` のままである。

画面の選択から実際のWorker計算・結果表示までブラウザでも確認した。最良火力3,556,623と再計算が一致し、テンション100を指定しないことと条件付き表示を確認した。

## 残る課題

利用者の保存所持品のJSONは未取得。標準プロフィールと公開検証値を使った計算で、実機の数値・ゾーン維持・暴走頻度・AI選択率は未照合。最良案の行動順と先制は未達であり、敵領域・ガード短縮・解除・ギガアタック等も未対応。355万を実行可能性や勝利の保証として扱わない。

普通の状態での弱い下限と、状態が揃ったときの強い手順を区別し、必要条件を満たせるか判断する材料にする。次は実機の装備と状態に照らした検証、行動順、条件付き案の必要状態を減らす比較を優先する。
