# 主力の準備と複数補助をまとめた手順比較

## 問題

攻撃スキルを起点にする比較では、主力の準備＋補助1人、または準備なし＋補助2人までが中心だった。主力の準備・3人の補助を合わせると強い構成や、初ターンの祈りから翌ターンにアンコールへ切り替える構成が、この比較経路に存在しなかった。

## 変更

- 習得済みスキルから、主力の準備と補完する複数補助を一組にした候補を作る。重複する強化の種類を避け、複数人のアンコールは候補として残す。
- 固定のダメージ倍率で優劣を決めない。補助の種類の広がりを候補の優先順にだけ使い、実際のダメージ・対象・MP・持続・回数制限は同じ戦闘計算で確認する。
- 祈り等の補助の後、待機になる翌ターンを、習得済みアンコールに切り替える案も比較する。回復する既存の行動は待機扱いで上書きしない。
- 各ターンに実際に行うスキルで順番を作る。祈りを行う初ターンは主力より前、アンコールへ切り替えたターンは主力の後、という経路も比較する。真魔解放の自動攻撃は戦闘エンジンがその場で処理する。
- 同じ装備・行動・条件の計画を重複評価しない。重複を飛ばした件数を返す。

候補の組合せは各キャラ最大5選択、全体512組まで検討し、優先候補を最大8件に絞る。これは探索候補の近似的な絞り込みであり、最適性の証明ではない。

## 統合

通常の前段探索は変更せず、役割から生成した編成を追加比較する既存の最終枠に接続する。元の結果を保持し、残りの総件数・総時間の範囲だけで実行する。固定・除外・所持数・解放・確率・速度の最終検査は維持する。

`strategyTeams.macroCalls` と `duplicatePlans` で実行状況を確認できる。`complementaryMacros:false` で従来の追加比較へ戻せる。1ターンの準備＋再行動の網羅、準備ターンの自由な移動、新しい候補に対する速度再調整の予算配分等は継続課題。

## 比較と限界

`npm run benchmark:support` は、仮の基礎能力を明示した構造ケースで、特盛・祈り・ロンド・真魔解放、翌ターンのアンコールを独立した参考手順として比較する。AIが指定呪文を選ぶ成立時条件を含み、実機ダメージ・成立率の再現ではない。

同じ192件上限で、従来の実評価42件・41,192に対し、新比較は88件・52,020。参考手順に到達し、MP・所持数と再計算一致を確認した。実評価件数は増えており、高速化の証明にはしない。新比較では同一計画25件の重複を回避した。

探索全体では、白領域の既存構造ケースの最良300,496を保持したが火力向上は未確認。別の制御ケースでも200/400/1,000件上限の最良値は維持した。すべての入力で改善・維持を証明したわけではない。元の編成や計算値を捨てずに候補を追加する段階であり、探索全体の置き換え完了ではない。

比較方法：

```
npm run benchmark:support
node scripts/benchmark-search.cjs --spell-only --without-complementary-macros
node scripts/benchmark-search.cjs --spell-only
```
