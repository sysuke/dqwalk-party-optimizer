# 攻略案と結果調整の再設計

目的は、攻略コンテンツに対して利用者の所持品から試す価値のある装備・手順を提案すること。全組合せの最適性を第一目標にしない。合法な手順、条件の明示、参考編成に対する探索品質を優先する。既存の戦闘計算・保存形式は段階的に引き継ぐ。

## 実施順と完了条件

1. 品質測定と結果からの修正（着手・初期実装済み）
   - `npm run benchmark:search` で固定参考手順と探索結果を同じ計算条件で比較。入力・探索上限をケースに保存する。
   - 現在のケースは物理の2/5/9ターン・MP制約の構造検証。実機再現や完成した品質基準とはしない。
   - 出力には参考手順比、資源条件、行動順、探索件数、時間切れ、所要時間を別々に出す。火力だけ上回っても実行可能性の合格にしない。
   - 結果に採用職業レベル、使用武器所持数、敵HP・守備力の編集を追加。所持品・レベルはプロフィール、敵は今回の敵条件へ保存して再探索する。保存不能ならプロフィールを変更しない。
2. 代表的な攻略案を基準ケース化（呪文の初期ケース追加、継続）
   - 紫領域＋継承呪文、物理ブレイク、バハムート長期戦、武器不足、速度装備の競合。
   - 手動参考手順に装備・状態・補助対象・開幕消費・手順・出典を保存。実測条件が足りないものは構造ケースと区別する。
   - 固定手順自体の計算誤差と、自動探索の取りこぼしを別々に報告する。未知の値を観測ダメージへ合わせない。
3. 攻略の型を入口にした探索へ置換（役割候補の追加比較を実装、全体置換は未完）
   - 敵に適した主力スキルだけでなく、領域・継承・再行動・回復を含む役割構成を候補化。
   - 必要な補助装備と所持数を確保してから装備を最適化。単独火力による早期除外を弱める。
   - 準備と発動を一まとまりとして比較し、前段で不利でも後段で有利になる手順を保持。
   - 残す候補は攻撃スキルだけでなく必要条件・役割・行動順の違いでも多様性を確保。
   - 既存探索を比較用として保持し、同じ予算で基準ケースが改善する範囲から切り替える。
4. 結果中心の通常UI（直接編集・今回だけのキャラ固定/武器除外を実装、全体は未完）
   - 通常は攻略選択→目的→計算→攻略案。結果内で主力固定・装備代替・レベル・敵条件・対象付き手順を編集。
   - 「お試しの仮所持品」と「自分の登録済み所持品」を明確に区別する。既存在庫を自動でゼロにしない。
   - 通常条件とゾーン・テンション100等の成立時案を別枠にする。行動順未達の案は実行可能な推薦と混同しない。
   - 保存変更と今回だけの試算変更を明示的に分ける。現在の初期編集は保存変更だけ。
5. データと保守（継続）
   - 推薦順位を変える影響が大きい未対応効果・基礎値を先に調査。
   - 仮シールドを無視せず、仮値を変えたときの順位変化を比較する。
   - 新探索の検証後に旧入口・補修処理を削減。保存移行より前に旧IDを削除しない。
