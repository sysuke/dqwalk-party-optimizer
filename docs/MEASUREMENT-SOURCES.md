## 2026-10-28：変異フォースの適用経路

再取得はCONNECT 403となったため、前回保存したHTMLと現行コードを確認した。今回のウェブ再読成功とは扱わない。

`dragonfang` はカタログ上で無属性・`forceStrong: true`。SequenceEngineは、無属性技にフォースを付与した場合の属性選択と、通常フォースで属性補正を半減するかを別に扱う。変異が有効なら `forcedResistance: -50` を渡し、`forceStrong` の技では `force: false` として属性ダメージ補正の半減を避ける。`force: false` だけを見てフォース未付与と判断しない。

例えば、**合成テスト用**に素の属性耐性90%を置くと、変異-50ポイント後は40%、属性倍率0.60になる。これは元倍率0.10を単純に1.5倍する計算ではない。魔人の生イオ補正27%も、強化フォース扱いのこの経路では通常フォースの13%へ半減しない。これらは現行実装の確認であり、敵の実測入力を確定したものではない。

重要な未対応箇所は、SequenceEngineが遺跡強化4の**被ダメージ80%軽減を別枠として適用する処理を持たない**こと。属性耐性に80ポイントを足して代用すると、変異-50ポイントとの相互作用まで変わってしまう。種類耐性へ代用する場合も、敵テンションによる耐性増幅の対象になり得る。いずれも根拠なく置換しない。

診断へ `attributeHandling` を追加し、元属性・強化フォース扱い・報告されたフォース状態を表示する。被ダメージ軽減の合成位置は未確定なので、今回も80%軽減を実戦計算へ自動追加していない。

凍結1.10倍と強化軽減0.20倍を最後に乗算する限定的な仮定では、2段階切り捨ての順序差は最大1と数学的に確認した。[確認コードと転用できない条件](MEASUREMENT-ROUNDING.md)。合成方法そのものや現行エンジン全体の誤差幅を確定する結果ではない。

## 2026-10-28：公開参照実装との相違を修正

[AruDqw/dqw-damege-calc](https://github.com/AruDqw/dqw-damege-calc/tree/41ee7370c028227d6679a6facc995b912617309a)をHTTPS Git経由で取得し、固定コミットのREADMEとindex.htmlを確認した。index.htmlの `slashResTotal` は `(100 + slashResChange + suijaku + freeze + senisosshitsu) / 100` で、最初の切り捨て前の乗算群へ入る。READMEの全体フロー⑥⑦も同じ加算群を示す。

こちらのPhysicalCalculatorは、凍結とtypeDebuffを別々に乗算していた。参照式に合わせ、`(100 + typeDebuff + 凍結ポイント) / 100` を1つの被ダメージ倍率として適用するよう修正した。例えばtypeDebuff=20と凍結Lv1なら、従来1.20×1.10=1.32だったものが1.30になる。片方が0の場合は従来どおり。

診断の `factors.damageTakenGroup` が実際の合成倍率。既存のfreezeとtypeDebuffは個々の補正を示す参考値として残すため、両者を乗算して再構成しない。合成テストは凍結Lv1/Lv2と正負補正を確認し、独立に同じ合計ポイントを入力した結果・丸め過程と一致することを検証した。

実測記録の画面内訳も、合成倍率がある場合は「凍結＋斬体被ダメージ補正（合成）」だけを乗算一覧へ表示するよう修正。個別のfreeze/typeDebuffを重複した倍率として並べない。JSON内の既存フィールドとブラウザ保存キーは保持する。

この公開実装も実機内部式の公式資料ではない。また、遺跡強化の80%軽減を表す専用入力は確認できなかった。遺跡強化がtypeDebuffと同群だという根拠にはならないため、今回の修正に80%軽減のマッピングは含めない。実測4件の一致を主張する変更ではない。
