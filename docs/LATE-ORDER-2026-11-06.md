# 追加探索後の行動順・速度装備の再調整

## 問題

速度調整の後に、役割の組合せ・準備ターン・再行動の追加探索を行っていた。その段階で新たに見つかった手順は、順序未達の候補として記録されても速度調整に戻らず、先制・行動順必須の場合は最終出力から除外されていた。

また、同じ装備の候補をまとめる際に行動列を区別していなかった。実現可能な速度関係は行動列でも変わるため、片方だけを調べて済ませることはできない。

## 変更

- 先制・行動順を必須にした場合だけ、既存の速度調整枠の最大半分（上限96件）を追加探索後へ残す。総件数・締切は増やさない。通常の火力比較では新たな予約枠を取らない。
- 追加探索も予約枠を使い切らないようにし、後段では新しく見つかった手順を優先して調整する。残りの既存候補も対象とする。
- 装備だけでなく行動列・条件を含む計画全体で重複を判定する。すでに調べた同じ計画を繰り返さない。
- 速度関係が循環するなど、入力モデルと速度解析の上限内で両立しない手順は調整の対象から外す。数学的な速度関係の解析であり、所持品での成立可否を全列挙した判定ではない。
- 調整後は所持数・MP・解放・固定/除外・確率・生存等の既存検査を通し、先制・味方順も最後に厳密設定で再計算する。調整途中の未達候補を結果へ出さない。
- 速度装備の検討中にも締切を確認する。

`orderRepair.lateCalls` は後段の評価件数、`lateVerified` はその検証通過手順数、`lateNewVerified` は追加探索から来た手順の検証通過数。いずれも画面の候補カード数とは異なる。同一スキルの別案は表示時にまとめられる。

## 比較と検証

`late-order-2t` は仮基礎能力と架空の速度帽を使う構造ケース。独立した固定参考手順も、速度比1.2・敵速度上限50の条件内で先制と味方順が成立することを検査する。実機の速度や乱数を検証したものではない。

1,000件上限で、後段を無効にした場合は速度調整36件・検証通過3手順。後段ありでは計72件・検証通過6手順で、そのうち3手順は追加探索で見つけたもの。総評価件数は746→782、最良火力は142,928を維持した。全体火力の向上や高速化を示す結果ではない。

```
node scripts/benchmark-search.cjs --late-order-only --without-late-order-repair
node scripts/benchmark-search.cjs --late-order-only
```

テストでは、同じ装備で行動順が異なる2手順をそれぞれ調整し、順序が循環する手順を除外して別の手順へ予算を使うことも確認する。指定した先制・味方順を満たせない場合に出力しない既存の負例も維持する。

並行計測時に時間制限へ到達する例もあったため、経過時間を改善の証明には使わない。速度解析と装備探索は近似のままで、複数の装備を同時に替えないと不足が改善しない局所的な行き止まりや、限られた候補保持数による取りこぼしは残る。
