# 条件付きの火力案に、味方順を満たす別案を残す

## 問題

約355万の条件付き案は、主力が補助役より速く、そのままでは指定した手順の味方順を満たせなかった。火力だけでなく、実際に試すための装備・行動順の調整が必要だった。

単独の速度装備変更でも止まる場合があった。たとえば、主力を遅くするとさらに後ろの補助役を追い越せなくなり、後ろの補助役だけを遅くしても今ある速度不足が減らない。この場合、両者を同時に遅くする変更が必要になる。

## 変更

- 速度調整が止まった場合に、異なる2人の任意のこころ/防具枠を1つずつ外す候補を追加。両方の変更を完成させてから比較する。武器・職業・配置・継承・手順はこの変更では固定する。
- 同じ部位でなくても比較する。最大2,048組の安価な組立て比較から上位8候補を戦闘全体で検査し、通常の速度調整予算を使う。`pairedSpeedRepair:false` でこの追加だけを無効にできる。
- 条件付きの長期火力比較では、各ターンの味方順を最大24通りの共通順序に揃え、その後に速度装備を調整する工程を追加。アンコール等の追加行動は一組のまま移す。
- 全体予算から16%、最大160件を予約する。従来の長期手順修正枠とは別に確保し、全体の評価件数・締切は増やさない。`orderAlternative:false` でこの工程を無効にできる。
- 速度検査・MP・所持数・習得技・領域の色等を満たす案が見つかった場合だけ、火力優先案と別に結果へ残す。同じ攻撃スキルでも「味方の行動順を優先した別案」として表示する。
- 敵速度未入力なら、味方順が成立しても先制は未確認のまま。ゾーン・暴走・指定AI呪文の発動率も未算定のまま保持する。

この自動の別案工程は、3〜9ターン・火力比較・「主力ゾーン・暴走成立時」のプリセットに限定する。通常条件・周回・耐久の順位や目的は変更しない。既存の順序必須探索でも、速度調整自体は2人の同時除去を使用できる。

## 比較

```
npm run benchmark:roles -- --bahamut-order
node tests/conditional-order.cjs
```

標準のお試しプロフィール・零式・5ターン・同じ成立条件・全体1,000件上限で比較した。無効時は火力3,556,623で味方順未達。有効時は全体972件で、火力優先3,754,572と、味方順成立1,760,323を残せた。別案工程は134件、うち速度修正110件・2人の同時除去8件。再計算が一致し、プロフィールは変更していない。

味方順成立案の表示速度は左から621/951/768/1,143。入力した速度比1.2のモデルで全ターンの味方順を満たした。敵速度は未入力のため先制は未確認。確率効果の同時発動率は `null`、総合の `conditionsMet` は `false` のままである。

同じ固定手順を使った速度調整単体では、単独変更等は2,097,242・味方順未達で停止した。追加した2人の同時除去を含む調整では1,760,323へ火力を落とす代わりに、味方順を満たせた。これは火力最大化ではなく、速度条件との交換条件を見せる結果である。

ブラウザで新しい別案を展開し、条件付き表示、味方順の「モデル内で成立」、敵への先制未確認、再計算を確認する。

## 制限

全行動列や全装備の最適性を保証しない。共通順序の候補を評価してから1つの候補を速度調整する有限探索なので、他の手順・装備でより高い火力の順序成立案を取りこぼす可能性がある。装備を外す以外の複数部位の同時交換は未対応。

実ゲームの速度乱数、敵行動、耐久、ゾーン維持、暴走頻度、AI選択は未照合。実機の安定攻略や勝利を確認した結果ではない。必要な確率効果を減らす比較は今回未対応で、次の課題として残す。
