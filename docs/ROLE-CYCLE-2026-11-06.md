# 複数人の装備・手順の役割循環と低火力の基準化

## 役割循環

前回の2人交換は、途中で火力が下がる変更を受け入れられず、3人以上の装備を同時に回せば改善する場合に止まっていた。今回、同じ人物・職業・育成状態を保ったまま、装備と対応する手順を最大4人で配り直す候補を追加した。

- 主武器・左手・継承・凸数・こころ・防具・開幕効果を役割として移す。職業・レベル・こころ道・本人のゾーン等は人物側に残す。
- 行動の使用者と味方対象を一緒に付け替える。AI選択呪文や敵の対象番号は変更しない。
- 実機表示能力を指定した人物は移動させない。固定したまま、他の人物だけの循環は許可する。
- 従来の2人交換に加え、3〜4人が動く配分を比較する。候補生成は最大4人の24配分以内で、通常の職業変更候補と同じ評価予算を使う。
- 所持数、習得技、MP、バフ、シールド、指定した条件は通常の戦闘全体計算で再検査する。期限と総評価上限を維持し、評価済みの親手順を再評価しない。
- `rolePermutations:false` で追加した複数人配分だけを無効化できる。`roleAssignment.permutationCalls` は既存の役割再検査枠のうち、複数人配分の評価に使った件数である。

仮基礎能力と既存武器の構造ケースを追加した。2人交換は32,614で停止し、3人の役割循環は33,706へ改善した。所持武器各1本を維持し、3人の全6配分を戦闘計算した最良値と一致する。入力の不変、補助対象の付け替え、4人の循環、期限、資源不成立も検査する。これは行動順・先制が未達の構造例であり、実ゲームでの強さや攻略成立の証明ではない。

## バハムート零式の低火力報告

報告画面は零式・火力比較・5ターン・通常条件。保存所持品・育成状態のJSONは未取得で、同一入力の再現はできていない。代わりに標準のお試しプロフィールで、同じ敵・5ターン・通常条件を測定する入口を追加した。

```
npm run benchmark:roles
npm run benchmark:roles -- --bahamut
```

零式ケースは全戦闘評価1,000件・装備候補4,000件指定・30秒以内の比較。装備候補メトリクスには従来から補修検査も加算され、今回4,690件となった。役割循環の有無を同じ上限で比較する。採用案は通常の戦闘計算で再生する。実行時間や探索上限による結果変動はありうる。

初回比較の最良火力は両方202,880、行動順・先制は未達。SHTガードの発動はなかった。少なくともこのケースでは、低火力を99%ガードだけで説明できず、複数人配分だけでも改善しなかった。今回の更新で低火力問題を解決したとは扱わない。

次の優先課題は、通常条件で強い参考編成を入力・所持品・装備・補助・MPまで固定し、既知の手順と探索結果を直接比較すること。準備前の単発火力による候補絞り、共有するこころ/防具の配分、複数補助が成立する手順の取りこぼしを個別に調べる。敵耐性の恣意的な緩和や、未知の確率効果の確定扱いは行わない。

こころ・防具の再最適化や、複数人の職業と装備を同時に変更する探索は未対応。有限候補を予算内で比較するため、全編成の最適性は保証しない。
