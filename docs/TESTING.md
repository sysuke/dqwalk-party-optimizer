# テストの実行方針

## 普段の変更

- 画面の構造・基本導線: `npm run test:ui`。読み込み順、Worker起動、フォーム構造、コンテンツの重複・欠落、配信サーバーを確認する。
- 実測診断: `npm run test:measurements`。実測fixture・補正診断・トレース・計算機への入力を確認する。
- 特定の計算修正: 対象の `node tests/<file>.cjs` を実行する。関連ファイルが不明な場合は全件実行する。
- CSS・実際のクリック操作・スマホ表示はブラウザでも確認する。UIテストは簡易DOMを使うため、実ブラウザの代替にはならない。

実行対象だけを見るには `npm test -- ui --list` または `npm test -- measurements --list`。

## 反映前

`npm test` と `npm run check:pages` を実行する。全件実行は従来どおり tests 直下の全 `.cjs` を自動検出する。限定スイートに追加し忘れても、全件実行からは漏れない。

データ・実測を変更した場合は `npm run audit:data`、`npm run audit:measurements`、`npm run diagnose:measurements` も確認する。

## 整理の基準

計算の境界値、既知の不具合、在庫制約、保存互換、旧v8 fixtureの回帰確認は残す。説明文の一致・装飾の配置だけを固定する確認は増やさない。基本導線は文言よりフォームの入力名や遷移、コンテンツの重複・欠落を確認する。

今回、quickの画面チェックをUI側へ集約し、ヘッダー・フッターの装飾チェックを削除。詳細設定の説明文やボタンの文言・位置への依存を外した。読み込み順の確認はarchitectureに一本化した。

各ファイルの所要時間と遅い上位3ファイルを表示する。件数を目標に削除せず、重複する検証と時間のかかる条件を見て次の整理を判断する。
